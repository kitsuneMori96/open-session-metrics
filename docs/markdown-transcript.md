# transcript 的 Markdown 子集

状态：已实现（默认开启，工具栏 `md` 可关）
范围：把会话正文里的 Markdown 渲染成 OSM 自己的视觉语言，**不引入任何新颜色、字号、填充面或容器**。

---

## 1. 结论先行

transcript 是**仪表纸带**，不是文档。Markdown 若按文档语法渲染（六级标题、单元格边框、引用竖条、代码块填充），
会立刻把这一栏变成另一种界面——那种割裂来自文档排版本身，而不是「支持 Markdown」这件事。

所以这里不做文档语法，只做**减噪音**：解析器只产出能用既有词表表达的构造，无法表达的一律原样返回纯文本。

| 构造 | 落成的像素 | 新增词汇 |
|---|---|---|
| 标题 `#`…`######` | 去掉 `#`，`font-semibold text-ink`；h1–h2 上方 8 px，h3–h6 上方 3 px | 无（字重 + 留白） |
| 列表 `-` / `1.` | `·` 或原序号，放 3ch 固定槽；每级缩进 2ch，最多 4 级 | 无（复用数字槽位习惯） |
| 围栏 ` ``` ` | 左边一条 hairline，`pre-wrap`，无填充无边框（`.out` 的语汇） | 无 |
| 行内代码 `` ` `` | `bg-ink/5`（已上架的 5% 墨） | 无 |
| 粗体 `**` | `font-semibold` | 无 |
| 链接 `[x](y)` | ink + `rule-strong` 下划线；**不用 `flow` 蓝**（蓝已被「光标在此」占用） | 无 |
| 表格 `\| a \| b \|` | 默认按「记录行」铺开；含数字列时画 hairline 网格 | 无 |
| 引用 `>` | `│`（faint）+ `text-ink-soft` | 无 |
| 分隔线 `---` | 一条 `border-rule` | 无 |

**覆盖范围**：assistant 的正文与用户消息（`PromptRow` 那行 `>`）共用同一个 `Md`。本机 2 130 条 prompt 里
11.1% 含块级标记、7.9% 含行内标记——贴进来的设计稿和日志会带着 `##`、`**` 直接上纸带。
**不覆盖**：reasoning 行（默认折叠，且推理里混着未整理的半成品标记，渲染会假装它有结构）与工具
input/output（逐字保留，那是数据不是排版）。

**不解析、按纯文本显示**：图片、斜体（界面没有斜体）、脚注、引用式链接、字面 HTML（从不解释、从不进 `innerHTML`）。

## 2. 为什么是这九种，而不是更多

本机 9 615 段正文（`.data/metrics.db` 的 `parts.kind='text'`）实测：

| 项 | 值 |
|---|---|
| 纯文本（无任何标记） | 4 791 段 · **49.8%** |
| 只有行内标记 | 2 919 段 · 30.4% |
| 含块结构 | 1 905 段 · **19.8%** |
| 纯语法字符占比 | 152 745 / 2 339 470 字符 · **6.5%** |

块统计：段落 16 386 · 列表项 8 416 · 标题 3 554 · 围栏 1 246 · 表格 748 · 分隔线 533 · 引用 49。

标题层级：h1 261、h2 1 733、h3 1 621、h4 138、h5/h6 为 0。

去掉的 6.5% 全是读者不需要解码的字符（`##`、`` ` ``、`**`、`|---|`），剩下的正文一个字没动。

### 2.1 标题为什么不用 `.micro`

第一版把 h1–h2 落到 `.micro`（9 px、0.14 em 字距，即面板标签语汇），截图判定**不可接受**：
正文是 10 px，9 px 的标题读起来是「图注」，层级反了。

最终只用两种手段，都在词表内：**字重**（semibold）与**留白**（h1–h2 上方 8 px、h3–h6 上方 3 px）。
字号、颜色一律不动——这一栏只有一种正文尺寸，这条不破例。

### 2.2 表格为什么默认不画网格

748 张表：只有 **95** 张含数字列，**407** 张有超过 40 字符的长单元格，**608** 张是 2–3 列。

也就是说它们绝大多数是**记录表**（症状→成因、决策→落点），不是矩阵。画成网格时，列宽被最长的单元格撑开，
表格比 92ch 正文栏更宽，最右一列被裁掉；铺成行则与纸带其余部分同构，零溢出。

判据是 `isMatrix()`：任一列的所有非空单元格都是数字（含 `%` `×` `k` `M` `tok` `cr` 等后缀）才算矩阵。
`StackView` 首次出现列名（faint），每行以首列作 key（ink），其余列 ` · ` 连接后退一档软度。

### 2.3 围栏撞上 2 000 字符截断

`PART_CAP = 2 000`，本库 302 段卡在上限，其中 700 段含围栏标记。

一段被截断的围栏**没有闭合行**。解析器不报错、不吞后文：围栏一直延伸到文本末尾，照样按代码渲染。
显示上没有闭合标记，因为原文里本来就没有——补一个是谎言。

## 3. 实现

```
web/src/lib/md.ts         解析器（块 + 行内 AST，token 带源偏移），零依赖、无 innerHTML
web/src/components/Md.tsx 渲染器（BlockView / InlineView / 表格三视图）
web/src/lib/transcript.ts 搜索投影 plainText + 每行缓存（只在渲染开启时生效）
web/src/components/Transcript.tsx  md 开关；正文与用户消息走 Md，reasoning 与工具行不走
web/scripts/md-check.mjs  解析器断言（31 条），并入 pnpm test
```

`parseMd` 是单趟扫描，`parseInline` 不递归（只允许一层嵌套：粗体里包容行代码，语料里 ``**`tool.name`**`` 很常见，
不处理就会漏出字面反引号）。行内 token 带 `at` 偏移量，用于搜索高亮。

### 3.1 搜索：读到的文本 vs 存下的文本

搜索按**存下的文本**匹配，而开启渲染后读者看到的是没有标记的文本。两者差在标记字符上：

存下的：``1. **`opencode-terminal-progress`** - 显示 agent 进度``
读到的：`1. opencode-terminal-progress - 显示 agent 进度`

一句从屏上抄下来的 `1. opencode-terminal-progress - 显示` 在存下的文本里匹配不到——标记字符正好卡在中间。

- 过滤：`rowMatches(..., md)` 对 `kind === "text"` / `"prompt"` 的行改读 `plainText(searchText(row))`，
  按行 `WeakMap` 缓存（最大会话 1 628 段 / 387 k 字符，整表投影约 8 ms，每次输入只付一次）。
  工具输入输出**不投影**——它们不按 Markdown 渲染，其中的 `|`、`*`、`#` 是内容不是语法。
- 高亮：`findHits` 在**源串**上找命中，再按 token 的 `at` 裁剪，所以跨行内边界的命中两侧都能标上。
  原实现逐 token 调 `Mark`，跨边界时「匹配到行但不高亮」，已修。

### 3.2 虚拟列表

`estimateSize` 仍是 34 px（工具/推理行 22 px）。表格与折行列表让行高方差变大，但行是实测高度
（`measureElement`），实测未出现跳行；深度滚动时滚动条比例会轻微变化，属可接受。
若将来需更稳，可按块数给估值加权，不改渲染。

## 4. 验收门

| # | 门 | 判定 |
|---|---|---|
| 1 | 视觉词表 | `Md.tsx` 内只出现既有类名与布局工具；无新色值、新字号、新填充面、新容器 |
| 2 | 无 `innerHTML` | 全链路 React 元素，字面 HTML 原样显示 |
| 3 | 解析器断言 | `pnpm -F @osm/web test` 全绿（`md-check.mjs` 31 条 + `transcript-check.mjs` 31 条） |
| 4 | 行内偏移 | 每个 token 的 `at` 指向源串中自己的文本（脏数据样例逐条断言） |
| 5 | 截断围栏 | 未闭合围栏仍按代码渲染，不吞后文 |
| 6 | 表格 | 记录表零横向溢出；矩阵右对齐、`tabular` 数字 |
| 7 | 搜索 | 屏上可见的短语能命中并高亮；`plainText` 与渲染结果一致 |
| 8 | 关闭路径 | `md` 关闭后逐字回到原样（`localStorage["osm.md"] = "0"`） |
| 9 | 性能 | 最大会话打开与搜索无可感延迟（投影 8 ms / 首次） |

## 5. 已知边界

| 项 | 现状 |
|---|---|
| 嵌套 | 只允许粗体/链接里包容行代码；斜体、粗体里再套粗体不解析 |
| 斜体 / 图片 / 脚注 / 引用式链接 | 原样纯文本（界面没有对应语汇，强行渲染会造第二套排版） |
| reasoning 行 | 保持纯文本：默认折叠，且推理里混着半成品标记，渲染等于替它伪造结构 |
| 表格 > 4 列且无数字列 | 按记录行铺开，长单元格可能折行；这是相对网格更小的代价 |
| 查询含语法字符 | `**现有功能**` 不再命中（投影已去掉 `**`）；查可见文本即可 |
| 超长行 | 段落上限仍是 2 000 字符，与渲染无关 |
