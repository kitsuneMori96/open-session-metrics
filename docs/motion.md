# 动效

这套界面的动效只有一句话：**笔在动，不是卡片在弹**。

仪表盘的参照物是绘图仪——纸、发丝线、等宽字、零圆角。所以数值会滚、规则线会从左往右画、
面板会换内容，但没有弹簧、没有回弹、没有悬停放大、没有卡片从屏幕外飞进来。

实现分两半：`web/src/motion.css`（令牌 + 指针/遮罩类动词）和 `web/src/lib/motion.ts`
（图表重画的 keyed wipe 与内容指纹）。

## 令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--motion-fast` | 90ms | 指针态：颜色、边框、焦点、提示卡 |
| `--motion-middle` | 120ms | 字形转向：排序三角、展开箭头 |
| `--motion-base` | 170ms | 值变化：数字滚轮、遮罩落位 |
| `--motion-slow` | 260ms | 形状变化：图表重画 |
| `--motion-out` | 60ms | 离场（永远比入场快） |
| `--ease-mech` | `cubic-bezier(0.4, 0, 0.2, 1)` | 主曲线，取自数字滚轮 |
| `--ease-track` | `cubic-bezier(0.65, 0, 0.35, 1)` | 可逆过程：框选、抽屉 |
| `--stagger` | 12ms | 同批元素错峰（上限 5 个） |

**没有第五档时长。** 260ms 是上限（再长就是在等动画），90ms 是下限（再短只剩掉帧感）。

## 六个动词

| 动词 | 形态 | 用在哪 | 实现 |
| --- | --- | --- | --- |
| **Roll** | 数字逐位滚动 | KPI 数值 | `components/Roll.tsx`（原有的，动效语言的母版） |
| **Press** | 只变色，位移为零 | 按钮、输入框、表格行、链接 | `button/a/input/select/.grid-row` 的 90ms 颜色过渡 |
| **Ink** | 原地淡入 + 2px 上浮 | 提示卡（90ms 进 / 60ms 出）、⌘K 面板与结果行、首屏骨架 | `.ink` / `.ink-fast` / `.ink-out` |
| **Turn** | 单字形旋转 | 表头排序三角、展开箭头 | `.turn` + `rotate-*` |
| **Pulse** | 发丝线明暗呼吸 1.6s | **只给同步状态**（和首屏骨架） | `.pulse` |
| **Wipe** | `clip-path` 从左往右揭开 | 图表重画 | `useWipe()`，WAAPI，260ms |

### 为什么图表是 Wipe 而不是淡入淡出

淡入淡出时两张曲线各半透明地叠着，眼睛要同时解析两条形状。Wipe 永远只有一条曲线在屏幕上，
按阅读方向揭示，语义就是「重新画一遍」，也不需要额外画扫描线之类的装饰。

## 交互对照

| 交互 | 动作 | 时长 |
| --- | --- | --- |
| 指针进入按钮 / 行 / 字段 | Press | 90ms |
| 提示卡出现 / 离开 | Ink | 90ms / 60ms |
| 提示卡内容随指针更新 | 不动 | 0ms |
| KPI 数值变化 | Roll | 170ms |
| 换窗口、点 facet、框选松手 | 数字 Roll + 图表 Wipe | 170 / 260ms |
| 表格排序 | 表头三角 Turn，行序直接换 | 120ms |
| 展开 / 折叠子代理 | 箭头 Turn | 120ms |
| ⌘K 打开 | 遮罩 Ink、面板 Ink、结果行 12ms 错峰（≤5） | 90 / 170ms |
| 同步（↻） | 按钮 Pulse；数据落定后 KPI Roll + 图表 Wipe | 1.6s / 260ms |
| 首屏读取 | 骨架的发丝线 Pulse | 1.6s |
| 窗口 resize、滚动、无限滚动追加、轮询 | 不动 | 0ms |

## 什么绝对不能动

不是审美，是这几处一动画就出错：

- **提示卡的跟随位移**：缓动等于慢半拍，指针已经在下一列了。
- **虚拟化表格的行位移**：200 行时 FLIP 掉帧，而且滚动中重排会和锚点打架。
- **框选矩形**：必须逐帧跟手，任何 easing 都是 bug。
- **坐标轴刻度**：标签 tween 会出现 `10-2…10-21` 这种残影。
- **首屏、轮询、滚动追加**：这些不是状态变化，数据到了就直接画。

## 图表重画怎么触发

`Figure` 接受一个 `wipeKey`——调用方用 `fingerprint()` 把要画的数据折成一个短字符串：

```tsx
<Figure wipeKey={fingerprint(totals, `${buckets.length}:${lastTs}`)} …>
```

- 指纹相同 → 不画（轮询返回一样的内容时完全静默）
- 指纹变化 → 从右往左揭开，260ms，同帧的多张图按 12ms 错峰
- 首次挂载 → 不播（首帧就是最终状态）
- 只动 `clip-path` 一个属性，整张图一次动画，不是 200 个标记各动一次

## 无障碍与性能

- `prefers-reduced-motion: reduce` 时所有时长降到 1ms、错峰清零（`motion.css` 末尾）。
  `Roll` 自己也有分支，直接跳过滚轮。
- 只动 `transform / opacity / clip-path`；不动 `width / height / top / left`，也不动 SVG 的
  `r / x / y` 属性（要动就套 `<g>` 用 CSS transform）。
- 不使用 `transition-all`，不使用 `ease-in`（起手迟钝，像坏了）。

## 加动画之前

1. 这个变化是**用户动作**引起的吗？不是 → 不加。
2. 能用一个已有动词表达吗？能 → 用它，不要新造。
3. 时长在 90 / 120 / 170 / 260 里吗？不在 → 改到最近的档。
4. 只碰 `transform / opacity / clip-path` 吗？不是 → 重新想。
5. 跑一遍 `pnpm -F @osm/web test`：`scripts/motion-audit.mjs` 会拒绝 `transition-all`、
   浏览器缓动关键字、Tailwind 自带动画、`motion.css` 之外的 `@keyframes`、
   比例尺之外的时长，以及会动布局的 keyframes。
