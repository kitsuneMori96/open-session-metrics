# 套餐性价比：opencode Go 与 Qoder

状态：测量（`pnpm plans` 可复算）
数据快照：2026-10-24 16:19，`.data/metrics.db` 与 `.data/metrics-qoder.db`

用本机两个库自己记录的价格，算两份套餐的真实单价：`$10 → $80 计量额度` 与
`$20 → 2,000 credits`。所有单价都是「量出来的」，不是价目表抄来的——库里 `cost` 一列
就是这套程序算出的账单。

---

## 1. 结论

**按你的实测用量，Go 每轮便宜 1.87 倍、每 Mtok 便宜 2.06 倍，而它赢的全部来源就是那个
8 折额度。** 在 list 价下，Qoder 本来就比 opencode 付费档便宜 3.88 倍/Mtok（4.27 倍/轮）。

两边的「额度」看起来几乎一样大（1,804 vs 1,749 Mtok），纯粹因为价格也正好差 2 倍：

```
$10 Go   →  1,804 Mtok / 16,703 轮
$20 Qoder →  1,749 Mtok / 17,834 轮
```

这不是「性价比接近」，是「贵一倍、给一样多」。按每美元：Go 180.4 Mtok / 1,670 轮，
Qoder 87.5 Mtok / 892 轮。

---

## 2. 口径：套餐只是一个系数

一份套餐是「一个价格换一份额度」，它唯一改变的是单价：

```
effective = list × price / quota
```

- Go：`$10` 买 `$80` 计量 → `× 10/80` = 八分之一（`$0.04457 → $0.00557/Mtok`）
- Qoder：`$20` 买 `2,000 credits` → `× 20/2000` = **一 credit 一美分**，这是套餐自己的
  定义，不是我们编的汇率

所以两个套餐能放进同一个美元坐标系；差别只在「list 价差多少」与「折扣补回多少」。

## 3. 两端实测 list 价

只看 `cost > 0` 的轮次算单价——把免费档混进分母会把 opencode 的单价稀释到毫无意义：

```sql
SELECT COUNT(*) turns,
       SUM(input + output + reasoning + cache_read + cache_write) AS tok,
       SUM(cost) AS cost
FROM turns
WHERE role = 'assistant' AND cost > 0;
```

| | opencode 计量档 | Qoder |
| --- | ---: | ---: |
| 会话 | 26 | 19 |
| 轮次 | 6,290 | 6,286 |
| token | 679.3 Mtok | 616.6 Mtok |
| 计量成本 | **$30.127** | **704.958 cr**（= $7.05） |
| 每轮 | $0.004790 | 0.112147 cr = $0.001121 |
| 每 1k 轮 | $4.79 | 112.15 cr = $1.12 |
| 每 Mtok | **$0.04435** | **1.14325 cr = $0.01143** |
| 谁便宜（list） | — | **Qoder 3.88× / Mtok，4.27× / 轮** |

### 为什么 opencode 的混合价只有标价的 1/6.3

`turns.cost` 里 93.8% 的 token 是缓存读，账单被它自己的价目结构压扁了：

| 类别 | 量 | 价 | 金额 | 占账单 | 占 token |
| --- | ---: | ---: | ---: | ---: | ---: |
| cache read | 637.4 Mtok | $0.027 | $17.20 | 58.2% | 93.8% |
| input | 37.2 Mtok | $0.278 | $10.33 | 35.0% | 5.5% |
| output | 2.4 Mtok | $0.430 | $1.01 | 3.4% | 0.3% |
| reasoning | 2.4 Mtok | $0.424 | $1.00 | 3.4% | 0.3% |

（`re-priced` 用今天的价目重算得 `$0.04349/Mtok`，记录的 `$0.04435` 略高——差额来自
几行在价目变更之前物化的轮次。两侧都是测量值，差 2% 不影响结论。）

这就是为什么「Go 便宜」这个结论**完全依赖缓存命中率**：你的用法已经是 opencode 计价
最有利的形态，即便如此它也只领先 1.9 倍。缓存一掉，opencode 的混合价就向 `$0.28/Mtok`
靠，Go 的有效价跟着涨到 `$0.035/Mtok`——**零缓存时比 Qoder 的 `$0.01143` 还贵 3 倍**。

## 4. 套餐有效价与买到的量

| 套餐 | 价 | 额度 | 每轮 | 每 Mtok | 买到轮次 | 买到 Mtok | 覆盖天数 | $/30 天（各自负载） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| opencode Go | $10 | $80 | **$0.000599** | **$0.00554** | 16,703 | 1,804 | 27.4 | 10.93 |
| Qoder | $20 | 2,000 cr | $0.001121 | $0.01143 | 17,834 | 1,749 | 39.7 | 15.11 |

覆盖天数与 `$/30 天` 都按各自源的实测日烧算：

```sql
-- 分母只数「有计量的天」，不把离开机器的空白日算成零消耗
SELECT COUNT(DISTINCT date(created/1000,'unixepoch','localtime')) AS days,
       SUM(cost) AS cost, COUNT(*) AS turns
FROM turns
WHERE role = 'assistant' AND cost > 0 AND created >= :since;   -- since = 最后一轮 − 30 天
```

- opencode：近 30 天里 10 个计量日，`$2.915/天`，620 轮/天
- Qoder：14 个计量日，`50.354 cr/天`，449 轮/天

**这两行不能直接排名**：620 与 449 轮/天是两个不同的负载。同样的活换算过去，
Go 是 `$9.0/30 天`（500 轮/天），Qoder 是 `$16.8/30 天`——1.87 倍，与单价一致。

## 5. 盈亏平衡

Qoder 要追平（按 token），credit 的真实价格必须降到：

```
$0.00534 / cr      （现在 $0.01000）
```

也就是 `$20` 要给 **3,746 credits**（现在 2,000），或把每轮从 `0.1121 cr` 压到
`0.0599 cr`。按轮次的平衡点是 `$0.00534/cr`，与 token 口径相同——两个口径指向同一个结论。

## 6. 三条必须先说的前提

1. **opencode 的 `$30.127` 是影子价，不是账单。** `deepseek-v4.1-flash-free` 在
   models.dev 上是 $0，`.data/model-overrides.json` 给了它 `$0.28/$0.42/$0.028`。
   整条 opencode 侧结论对这个数字**线性敏感**：真实 list 价只要达到影子价的 2.06 倍，
   两者就在每 token 上打平；若它确实免费，Go 的 $80 额度买不到你现在用的任何东西。
2. **77.1% 的轮次（21,174 轮，75.6% token）是 $0 免费档。** Go 对这些轮次一分便宜都
   占不到，它的价值只覆盖那 6,290 轮付费档。继续只用免费档，两个套餐都不需要。
3. **Qoder 的 token 是还原出来的上下文占用**（`context_usage_ratio × 该轮的窗口分母`），
   不是计费 token。分母按模型取：`qfmodel` = 180 000、`dfmodel` = 1 000 000（不是选择器
   显示的 200 000，见 `docs/qoder-source.md` §5.1）。25 个会话里有 4 个占用记录明显偏低
   （<80k tok/turn），剔除后 `1.13910 cr/Mtok`、`0.113174 cr/turn`；每 token 的倍数仍是
   **2.06**，每轮从 1.87 变 1.89。**两个口径给出同一个结论，所以 token 只作交叉验证。**

第 3 条里「哪些库的 token 是还原的」不是写死的，用的是与 `/api/status` 同一个探测
（见 `docs/source-scope.md` §6）：只有 `output/cache/reasoning` 全为 0 的库才跑这项检查。

## 7. 复算

```bash
pnpm plans     # 两库只读；未建的库跳过，不会创建空库
```

等价 SQL 全部在 `server/src/cli/plans.ts` 里，三个数字的定义是：

| 数字 | 定义 |
| --- | --- |
| 每轮 | `SUM(cost) / COUNT(*)`，`role='assistant' AND cost > 0` |
| 每 Mtok | `SUM(cost) / (SUM(input+output+reasoning+cache_read+cache_write) / 1e6)` |
| 有效价 | `list × price / quota`，`quota` 是套餐给的额度 |

数字会随增量入库缓慢漂移（两分钟一轮）。本文表格是 16:19 的快照，`pnpm plans` 打印的是
当下值；两者差值应在千分位。

## 8. 结构性判断

Go 的八折不是「便宜」，是把 opencode 原本昂贵的 list 价补回来一部分。你的用法（九成
token 走缓存）恰好是它最有利的形态，这才让它以 1.9 倍领先一个每 Mtok 便宜近 4 倍的对手。

Qoder 的优势在于**计量对缓存结构不敏感**：正常日恒定在 `0.9–1.2 cr/Mtok`，长上下文、
零缓存、全输出都在同一档。代价是它把这件事藏在 credit 里——你看不到 token 账单，也就
无法像 opencode 这样用缓存命中率去优化单价。

按目前的条件：要单价选 Go，要「一个月固定花多少钱、不用盯缓存」选 Qoder。
